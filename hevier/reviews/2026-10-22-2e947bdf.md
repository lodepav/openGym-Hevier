# Review of the whole fork, 2026-10-22 (hevier/main 2e947bdf)

Three passes over `main...hevier/main` (365 files, ~27,000 lines): `/ponytail-review`, `/code-review`
and `/security-review`. Load assumed: one person, one or two phones. Nobody read every line. Each pass
went by risk: native plugins, network and the Hevy key, data that rewrites itself, and the newest
work (D79–D81).

## Security

**No vulnerabilities found** above the 80 % confidence bar. Checked: exported components, the widget's
route (only `/calendar` is accepted), PendingIntents (explicit, immutable), the strap file name
(sanitised, no path traversal), the Keystore secret (AES-GCM, fresh IV, private prefs, never in S),
the Hevy calls (fixed host, ids URL-encoded), the gym search (fixed hosts, numbers only), the update
notice (64-hex checksum needed, checked natively), no `dangerouslySetInnerHTML`, the release tools
(no shell splicing, pinned checksums). A known limit of upstream's design: the APK's checksum comes
from the same release as the APK, so it proves the download is intact, not who made it. The APK
signature does that.

## Must fix

1. **Two export passes at once can send a workout to Hevy twice** (`hevier/lib/hevy-export-sync.js` `sendToHevy`)
   - **What:** a pass is "let go" after 5 min (`PASS_MS`), because upstream's page reads have no timeout.
   - **Problem:** being let go does not stop it. `running` is cleared, the next trigger starts a second pass on the same state, and when the first wakes up, both POST the same workout. Hevy's API cannot delete, so the copy stays.
   - **Fix:** a pass number. `sendToHevy` raises it, and `exportOnce`'s `off()` also stops when the pass is no longer the current one. About 4 lines.
   - **Source:** ponytail.
2. **Strap drops leak Bluetooth connections** (`HevierHrStrapService.java:152`)
   - **What:** after a drop, `retry()` schedules a reconnect, and `find()` may reconnect first under the strap's new address.
   - **Problem:** `connect()` sets `gatt` without closing the one already there. The older connection stays open and its callbacks are ignored. Android has few GATT slots, so after a few drops in a long workout, connects start to fail.
   - **Fix:** in `connect()`, close an existing `gatt` before `connectGatt`, and cancel the pending retry. 3 lines.
   - **Source:** code-review, confirmed.
3. **Picking another strap during a workout keeps recording the old one** (`hevier/lib/hr-strap-run.js:116`)
   - **What:** `sync()` returns early when a recording for this workout is already running.
   - **Problem:** it compares only the workout id, not the address. Settings shows strap B as "Records your workouts", while strap A, which may be silent, is the one recorded.
   - **Fix:** keep the address that started the recording, and restart when it differs. 2 lines.
   - **Source:** code-review, confirmed.

## Should fix

4. **A "connected" callback that carries an error never retries** (`HevierHrStrapService.java`, `onConnectionStateChange`)
   - **What:** `STATE_CONNECTED` with a status other than success matches neither branch.
   - **Problem:** the service stays in "connecting" for the rest of the workout when the strap's name is its address, or the scan finds the same address.
   - **Fix:** treat any non-success status as a drop, `retry()`. 1 line.
5. **The live heart rate skips the off-skin check** (`hevier/lib/hr-strap-run.js:173`, `Service.record`)
   - **Problem:** a reading flagged "no skin contact", or a value of 255, shows in the header, on the full screen, in its zone and in the notification. The saved workout leaves it out (`plausible`).
   - **Fix:** show `live.last` only when `plausible(decodeHrm(r.hex))`. 1 line. On the native side, skip the notification text the same way.
6. **A recording can be left on the phone, or merged twice** (`hevier/lib/hr-strap-run.js:110`)
   - **Problem:** when the open workout is swapped for another, `settle(prev)` runs right after `H.stop()`, before the service has cleared its session, so `clear()` refuses to delete. The next launch's sweep merges it again (an extra sync-stamped edit) and deletes it.
   - **Fix:** wait for the `'off'` state event, or give it the same 1.5 s grace the other path has.
7. **The strap's settle runs on a timer outside the one-at-a-time queue** (`hr-strap-run.js`, `setTimeout(() => settle(prev), 1500)`)
   - **Problem:** if the saved workout lands later than 1.5 s after the session closes, `settle` finds neither the workout nor the session and deletes the recording. Plausible, not seen: today the save writes both in one update.
   - **Fix:** queue it (`queue = queue.then(() => settle(prev))`) and keep the file until a workout with that id exists, or until the next launch.

## Nice to have

8. **The full heart-rate screen redoes all its work every second** (`components/StrapScreen.jsx:76`): it copies the whole sample list on each reading and runs `summary()` and `zoneTimes()` over all of it, twice a second. In a 2-hour workout that is about 7,000 samples. Running totals in the buffer would make it O(1).
9. **`workoutSamples()` has no in-flight guard** (`hr-strap-run.js`): each reading that arrives before the first load finishes reads and parses the whole file again, and readings between the read and the cache are lost from the list. Cache the pending promise, as `plugin()` does.
10. **Settings keeps showing "Connected · N bpm" after the strap goes quiet** (`components/StrapSection.jsx`): nothing re-renders it. Use `StrapBpm`'s ticking clock, or re-render on a 5 s timer while connected.
11. **The Strength levels list (and exercise details) don't follow a change of the 1RM formula until a workout changes** (`views/StrengthLevels.jsx`, the `useMemo` keys). Rare. Adding the formula setting to the keys fixes both pages.

## Notes, not findings

- **Garmin "Broadcast heart rate" (parked):** a likely cause is in `onDescriptorWrite`. A watch that wants a bonded link answers the notification subscription with an authentication error, and the service then disconnects and retries for ever: "found, no heart rate". Worth logging the status there when this is picked up.
- Without tests: `hevy-export-sync.js` `sendToHevy` (its `exportOnce` is tested), `hr-strap-run.js`, `stopwatch.js`, `still-training-run.js`. Finding 1 deserves a test with its fix.

Verdict: fix 1–3 first; 4–7 are small and in the same files.
